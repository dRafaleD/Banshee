# Banshee v0.3.0

This alpha release widens file inspection to more formats (Mach-O, RTF, .NET,
Authenticode, scripts, email, disk images, JAR and APK), adds `strings` and
`hexdump`, writes SARIF logs and makes the console remember its history. Report
and rule schemas stay at version 1; new report fields are optional and omitted
when empty, so existing consumers keep working.

## Highlights

- **More formats.** Mach-O and universal binaries, RTF documents, .NET
  metadata, Authenticode signer details, PowerShell/VBScript/JScript/HTA/batch
  scripts, `.eml` messages, ISO and CAB listings, and JAR and APK packages.
  Each reports what it can see from the file alone and never runs or
  decompiles it.
- **ELF hardening checks.** Executable stacks, non-PIE dynamic executables,
  entry points outside executable segments, non-standard interpreters,
  RPATH/RUNPATH or libraries in temporary and relative paths, UPX markers and
  missing section headers. `$ORIGIN` paths are not reported.
- **SARIF output.** `report --format sarif` and `scan --format sarif` write a
  SARIF 2.1.0 log for code-scanning tools. Rule IDs name the finding source
  and kind; levels follow severity.
- **Strings and hex.** `banshee strings` (ASCII and UTF-16LE, with offsets and
  `--interesting` categories) and `banshee hexdump`.
- **Console history.** `history`, `!N`, `save <file>` and `run <file>`.
- **Rules.** Wide (UTF-16LE) matching, size bounds and proximity conditions;
  YARA import and export follow, and all 60 AsphDex library rules convert.

See the [changelog](../../CHANGELOG.md) for the full list.

## Compatibility

- Existing files can now show new findings: ELF and Mach-O hardening notes,
  script, email and document findings, and the expanded text and HTML report
  lines. Exit status with `--fail-on-findings` follows the findings, so a
  pipeline that gated on a clean result may need its baseline refreshed.
- Report JSON gains optional fields (for example `universal_architectures`,
  .NET and Authenticode sections). Fields are omitted when empty.
- Executable signature, linker and dependency labels follow the format (for
  example "Code signature present" for Mach-O).
- YARA import no longer misreads rule boundaries when a regex string contains
  `{` or `}`.

## Downloads

Packages are built for Windows x86_64 (MSVC), Linux x86_64 and ARM64 (GNU) and
macOS Intel and Apple Silicon, each with a SHA-256 sidecar and verified build
and SBOM attestations. Verify the checksum before extracting. Linux packages
require a compatible glibc.

## Limits

Banshee remains alpha software. Findings and secret detection are heuristic.
Authenticode, SPF/DKIM/DMARC and JAR/APK signing details are read, not
verified. Bytecode and DEX code are not decompiled. Evidence hashes check
consistency, not the identity of the evidence creator. JWT inspection is not
signature verification unless you run `jwt verify`; certificate checks are
offline and do not query revocation services. Review sensitive output before
sharing.
