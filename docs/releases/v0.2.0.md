# Banshee v0.2.0

This alpha release adds an interactive console, deeper file and script
analysis, new report and export formats, and a browser build. Report and rule
schemas stay at version 1; new report fields are optional and omitted when
empty, so existing consumers keep working.

## Highlights

- **Interactive console.** Run `banshee` on a terminal (or `banshee shell`) to
  get a `banshee>` prompt where commands are typed without the `banshee`
  prefix. `help` groups commands by category, Tab completes commands, flags,
  flag values and paths, and `open <file>` keeps a file for the session (use
  `@` for it, or type `report` alone). `tr` / `en` switch the console between
  Turkish and English. History stays in memory. Pipes and scripts are
  unaffected.
- **Turkish output.** `--lang tr` (or `BANSHEE_LANG=tr`) translates the help
  menu, options and the labels of `whatis`, `entropy`, `jwt inspect`,
  `hash identify` and `timestamp`. JSON, reports, rule and finding texts stay
  English so scripts and shared reports do not change with the language.
- **Deobfuscation.** UTF-16LE layers, single-byte and repeating-key XOR inside
  Base64/Hex payloads, and rewriting of character-code arrays, `\xNN` escapes,
  string concatenation, PowerShell format strings and reversed literals. Nothing
  is executed.
- **More file formats.** Office (OOXML and OLE), PDF and Windows shortcut
  inspection; PE import hash, Rich header, TLS callbacks and per-section
  entropy (import hashes matched pefile on 300 local system binaries).
- **Reports and sharing.** Script-free HTML reports, STIX 2.1 / MISP / CSV
  export of observables, ssdeep similarity in `diff`, and optional MITRE ATT&CK
  tags on rules.
- **Rules.** Conversion to and from a documented YARA subset.
- **Fewer false positives.** Domains are validated against an embedded IANA TLD
  snapshot, so identifiers such as `System.Net.WebClient` are no longer reported.
- **Tooling.** `doctor` checks the installation offline, `scan --jobs` analyzes
  files concurrently with byte-identical output, and `scripts/build-web.ps1`
  builds a single-file browser page that analyzes files locally in WebAssembly.
- **Hardening.** Ten fuzz targets (clean in a 64M-execution campaign), explicit
  size limits on every file read, and fixes for two panics found by fuzzing.

See the [changelog](../../CHANGELOG.md) for the full list.

## Compatibility

- The `line-editor` Cargo feature (on by default) adds `rustyline` for Tab
  completion. Builds without it, including the browser build, read plain lines.
- `scan` reserves its `--max-total-size` budget by each file's declared size in
  path order, so skip decisions no longer depend on concurrency.
- `xz` and `crypto-verify` remain default features. Without them XZ payloads
  are identified but not decompressed and signature checks report
  `unsupported`.

## Downloads

Packages are built for Windows x86_64 (MSVC), Linux x86_64 and ARM64 (GNU) and
macOS Intel and Apple Silicon, each with a SHA-256 sidecar and verified build
and SBOM attestations. Verify the checksum before extracting. Linux packages
require a compatible glibc.

## Limits

Banshee remains alpha software. Findings and secret detection are heuristic.
Evidence hashes check consistency, not the identity of the evidence creator.
JWT inspection is not signature verification unless you run `jwt verify`;
certificate checks are offline and do not query revocation services. Review
sensitive output before sharing.
